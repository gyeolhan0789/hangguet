# 내 담당: 기술 조사

[← 내 담당 문서로 돌아가기](README.md)

> 말투·속도·군말(언어)과 시선·표정(비언어)을 뽑아내는 기술, 그리고 이를 답변 내용과 묶어 "장면 단위 피드백"으로 만드는 방법을 조사한다.

조사일: 2026-10-12 · "확인 필요" 표시는 공식 문서로 확인하지 못했거나 직접 테스트해 봐야 하는 것.

## 0. 한눈에 보기

| 신호 | 무엇을 보나 | 후보 기술 | MVP 후보 |
|---|---|---|---|
| 받아쓰기 | 답변 텍스트 + 단어별 시각 | RTZR, CLOVA Speech, Whisper(+WhisperX) | **RTZR (결정)** |
| 말 속도 · 쉼 | 초당 음절 수, 긴 침묵 | STT 단어 시각, Silero VAD | STT 단어 시각으로 계산 |
| 군말 | "음, 어, 그, 약간, 뭔가" | 군말을 지우지 않는 STT + 단어 목록 | RTZR 군말 필터 끄기 + 단어 목록 |
| 말투 | 어미 혼용, 반복어, 흐지부지 끝맺음 | Kiwi(형태소 분석), LLM | Kiwi + 규칙 |
| 목소리 | 높낮이 변화, 크기, 떨림 | Praat(parselmouth), openSMILE, librosa | parselmouth |
| 시선 | 화면(카메라)을 보는가 | MediaPipe 눈 블렌드셰이프·홍채, L2CS-Net | MediaPipe (브라우저) |
| 표정 | 미소, 굳은 표정, 찡그림 | MediaPipe 블렌드셰이프 52개, 감정 분류 모델 | MediaPipe 블렌드셰이프 |
| 고개·자세·손 | 고개 돌림, 몸 흔들림, 얼굴 만지기 | MediaPipe 변환 행렬, Pose, Hand | 고개 방향만 |
| 묶기 | 신호 + 답변 문장 → 장면 피드백 | 공통 시간축 이벤트 + LLM | 문장 단위 장면 + LLM 문장화 |

## 1. 언어 신호

### 1-1. 받아쓰기(STT): 모든 언어 분석의 출발점

속도·쉼·군말을 재려면 **텍스트만이 아니라 단어마다 시작·끝 시각**이 있어야 한다. 그리고 **군말을 지우지 않아야** 한다. 대부분의 STT는 읽기 좋게 군말을 지우는 게 기본값이라 이 점이 가장 중요하다.

| 후보 | 단어 시각 | 군말 | 형태 | 비고 |
|---|---|---|---|---|
| RTZR(리턴제로) API | `use_word_timestamp` 옵션 (기본 꺼짐) | `use_disfluency_filter` 기본 **켜짐** → 끄면 남길 수 있음 | 유료 API, 파일·스트리밍 | 한국어 특화. 파일 2GB · 4시간까지. 단어 시각 응답 형식은 확인 필요 |
| CLOVA Speech (네이버 클라우드) | `words: [시작ms, 끝ms, 텍스트]` (기본 켜짐) | 군말 관련 옵션이 문서에 없음 → **확인 필요** | 유료 API | 화자 분리, SRT 출력 지원 |
| Whisper (OpenAI API / 오픈소스) | 기본은 문장 단위이고 몇 초씩 틀릴 수 있음 | **대부분 지움** (학습 데이터에서 군말을 지움). 프롬프트로 일부 살릴 수 있지만 없는 말을 지어낼 위험 | API 또는 GPU 서버 직접 운영 | 군말 분석에는 불리 |
| WhisperX | wav2vec2 강제 정렬로 단어 시각을 보정 | Whisper와 같음 | 오픈소스, GPU 필요 | 한국어 정렬 모델 품질 확인 필요 |
| Google Cloud STT | 단어별 시작·끝 제공 | 확인 필요 | 유료 API | 비교 기준용 |

- 한국어 "단어"는 띄어쓰기 단위(어절)라서 영어보다 단위가 크다. 쉼과 군말을 재는 데는 충분하다.

**결정: RTZR을 쓴다.**

- 이유: 한국어 특화 API이고, **군말 필터를 끌 수 있다고 문서에 나와 있는** 유일한 후보다. 단어 시각 옵션도 있다.
- 설정: `use_disfluency_filter: false`(군말 남기기), `use_word_timestamp: true`(단어 시각 받기)
- 확인할 것: 군말이 섞인 녹음 3개로 ① 군말이 실제로 남는지 ② 단어 시각 응답 형식과 정확도를 확인한다.

### 1-2. 말 속도 · 쉼

| 지표 | 계산 | 필요한 것 |
|---|---|---|
| 말하기 속도 | 음절 수 ÷ 전체 답변 시간 (쉼 포함) | STT 텍스트 (한글 1글자 = 1음절) |
| 조음 속도 | 음절 수 ÷ 실제 말한 시간 (쉼 제외) | 단어 시각 또는 VAD |
| 긴 쉼 | 단어와 단어 사이가 N초 이상 벌어진 구간 | 단어 시각 |
| 첫 반응 시간 | 질문이 끝나고 첫 단어가 나오기까지 | 질문 종료 시각 + 첫 단어 시각 |

- 한국어 연구에서는 속도를 **초당 음절 수(SPS)**로 재고, 쉼을 포함한 "말하기 속도"와 쉼을 뺀 "조음 속도"를 나눠 본다.
- 나이·성별에 따라 속도가 유의하게 다르다는 연구가 있다. 그래서 **정답 속도를 하나로 정하기 어렵다**. 아나운서 연구에서도 분당 몇 자라고 정하기 어렵다고 했다.
  → 절대 기준보다 **본인의 평소 속도와 비교**하는 쪽이 낫다. 예: "이 답변만 평소보다 30% 빨랐어요."
- 발음 평가 연구에서는 철자보다 **음절 기준** 속도가 점수를 더 잘 설명했다.
- 아나운서 낭독을 분석한 연구에서는 속도가 바뀔 때 음절 길이보다 **쉼 길이**가 주로 달라졌다. 쉼은 따로 볼 가치가 있다.
- VAD(말소리 구간 감지)는 Silero VAD 같은 가벼운 모델이 있다. 브라우저에서도 돌릴 수 있어 실시간 반응 로직과 함께 쓸 수 있다.

### 1-3. 군말

- 군말을 남기는 STT 결과에서 **목록 대조**로 찾는다.
  - 소리형: 음, 어, 으, 아
  - 습관어: 그, 저, 이제, 약간, 뭔가, 그러니까, 사실, 좀
- 습관어는 정상적인 뜻으로도 쓰인다("저는", "그 프로젝트"). 그래서 **형태소 분석(Kiwi)으로 감탄사·부사인 경우만** 세거나, 문맥을 LLM에 맡긴다.
- 연구용으로는 군말까지 그대로 받아쓰도록 학습한 모델(CrisperWhisper 등)이 있다. 영어 중심이고 비상업 라이선스(CC-BY-NC-4.0)라 참고만 한다.

### 1-4. 말투 (텍스트)

| 볼 것 | 방법 |
|---|---|
| 어미 혼용 ("~요"와 "~습니다") | Kiwi 형태소 분석으로 종결어미를 세기 |
| 같은 단어 반복 | 단어 빈도 |
| 흐지부지 끝맺음 ("~했던 것 같은데…") | 문장 끝 패턴 + LLM |
| 자신 없는 표현 ("~인 것 같습니다" 남발) | 패턴 목록 + LLM |

- **Kiwi(kiwipiepy)**: 파이썬으로 쓸 수 있는 한국어 형태소 분석기. 설치가 간단하고 빠르다.
- 규칙으로 잡기 애매한 것만 LLM에 넘긴다. 그래야 비용이 줄고, 같은 답변에 매번 같은 결과가 나온다.

### 1-5. 목소리 (음향)

| 지표 | 의미 | 도구 |
|---|---|---|
| 음높이(F0) 평균·변화 폭 | 단조로운지, 긴장해서 높아졌는지 | parselmouth |
| 크기(intensity) | 목소리가 작은지, 끝으로 갈수록 작아지는지 | parselmouth, librosa |
| 떨림(jitter, shimmer) | 목소리 떨림 | parselmouth |

- **parselmouth**: Praat(음성학 표준 도구)를 파이썬에서 그대로 부르는 라이브러리. 결과가 Praat과 같다. `pip install praat-parselmouth`
- **openSMILE**: 음성 감정 연구에서 많이 쓰는 특징 묶음(eGeMAPS)을 뽑는다. 같은 지표라도 Praat과 값이 크게 다를 수 있다는 연구가 있으니 **도구 하나만 골라 일관되게** 쓴다.
- 음높이는 남녀 범위가 달라 설정값(최저·최고 음높이)을 사람마다 맞춰야 한다.

## 2. 비언어 신호

### 2-1. MediaPipe Face Landmarker (중심 후보)

| 항목 | 내용 |
|---|---|
| 출력 | 얼굴 3D 점 **478개**(홍채 포함), 표정 점수 **52개**(블렌드셰이프), 얼굴 변환 행렬(고개 방향) |
| 구성 | 얼굴 감지(BlazeFace) → 얼굴 메시 → 블렌드셰이프 모델, 한 파일(`face_landmarker.task`)로 묶여 있음 |
| 실행 모드 | IMAGE, VIDEO(녹화 영상), LIVE_STREAM(웹캠 실시간) |
| 플랫폼 | Web(JavaScript), Python, Android |

- **브라우저에서 돌릴 수 있다**는 점이 가장 크다. 얼굴 영상을 서버로 보내지 않고 숫자(점수)만 보내면 개인정보 부담과 서버 비용이 함께 줄어든다.
- 같은 결과를 지웅(반응 로직)도 실시간으로 쓸 수 있다.

### 2-2. 시선

면접 피드백에 필요한 것은 "화면의 어느 좌표를 봤나"가 아니라 **"면접관(화면·카메라)을 보고 있나, 피하고 있나"**다. 정밀한 시선 추적까지는 필요 없다.

| 방법 | 내용 | 장단점 |
|---|---|---|
| ① 눈 블렌드셰이프 | `eyeLookUp/Down/In/Out` 점수 | 가장 간단. 대략적인 방향만 |
| ② 홍채 위치 | 눈꼬리 사이에서 홍채 중심이 어디 있는지 | ①보다 정밀. 직접 계산 필요 |
| ③ 고개 방향 | 변환 행렬에서 좌우·상하 각도 | 고개를 돌리는 회피는 이걸로 잡힘 |
| ④ L2CS-Net | 얼굴 이미지 → 시선 각도(ResNet-50) | 정확하지만 GPU 서버 필요. 웹캠과 약 1m 거리를 가정 |

- MVP는 **①+③**으로 "정면 / 아래 / 옆" 정도만 나눈다.
- 면접 시작 전에 3~5초 정면을 보게 해서 **본인 기준값**을 잡는다. 카메라 위치, 안경, 조명에 따라 값이 흔들리기 때문이다.
- 피드백 예: "2번 질문에서 '사실 그때는'이라고 말할 때 2.4초 동안 아래를 봤어요."

### 2-3. 표정

| 볼 것 | 블렌드셰이프 예 |
|---|---|
| 미소 | `mouthSmileLeft/Right` |
| 찡그림·긴장 | `browDownLeft/Right`, `mouthPressLeft/Right` |
| 눈 깜빡임 | `eyeBlinkLeft/Right` → 분당 깜빡임 수 |

- "기쁨·슬픔·화남" 같은 **감정 라벨 분류 모델**(FER, HSEmotion 등)도 있다. 다만 표정에서 감정을 읽는 것은 정확도와 타당성 모두 논란이 있다. AI 면접의 실효성·공정성 논란도 꾸준히 제기된다.
  → MVP는 감정 이름을 붙이지 않고 **"웃음이 거의 없음", "답변 내내 굳은 표정"처럼 관찰한 사실**만 말한다.
- 깜빡임이 많으면 긴장했다는 해석이 흔하지만 근거가 약하다. 참고 지표로만 둔다.

### 2-4. 자세 · 손 (나중에)

| 도구 | 출력 | 볼 것 |
|---|---|---|
| MediaPipe Pose Landmarker | 몸 점 33개 | 어깨 기울기, 몸 흔들림 |
| MediaPipe Hand Landmarker | 손 하나당 점 21개 | 얼굴·머리 만지기 |

웹캠에는 보통 상반신만 잡히고 손이 화면 밖에 있는 경우가 많다. MVP에서는 뺀다.

## 3. 답변 내용과 묶기 (장면 단위 피드백)

전체 기획의 핵심은 **"시선 72점"이 아니라 "어느 순간, 왜 그랬는지"**다. 그러려면 모든 신호를 같은 시간축에 올려야 한다.

### 3-1. 공통 시간축 이벤트

녹화 시작을 0ms로 두고, 모든 분석 결과를 같은 모양의 이벤트로 만든다.

```json
{"question_id": "q2", "type": "gaze_away", "start_ms": 83200, "end_ms": 85600, "value": {"direction": "down"}}
{"question_id": "q2", "type": "filler", "start_ms": 84100, "end_ms": 84400, "value": {"word": "음"}}
{"question_id": "q2", "type": "long_pause", "start_ms": 86000, "end_ms": 88900, "value": {}}
```

- 브라우저(MediaPipe)와 서버(STT·음성 분석)가 따로 돌아도 시각만 맞으면 합칠 수 있다. 녹화 시작 시각을 기준점으로 함께 저장한다.

### 3-2. 장면 만들기

```
STT 단어 시각 → 문장 단위로 자르기
  → 문장마다 겹치는 이벤트 모으기
  → 규칙으로 "짚어 줄 만한 장면" 고르기 (예: 시선 회피 + 군말 + 긴 쉼이 한 문장에 몰림)
  → LLM이 장면을 피드백 문장으로 바꾸기 (이벤트에 없는 사실은 말하지 않게)
  → 리포트: 피드백 + 해당 구간 영상 재생 (start_ms)
```

- 다빈 님 채점 결과(`question_id`, 판정, 지적)와 같은 `question_id`로 묶는다. 그러면 "내용은 좋았는데 이 부분에서 자신 없어 보였어요"처럼 **내용과 전달을 함께** 말할 수 있다.
- LLM에는 원본 영상이 아니라 **이벤트 목록 + 문장 텍스트**만 넘긴다. 다빈 님이 인용 문장이 원문에 없으면 피드백을 버리듯, 여기서도 이벤트에 없는 내용을 말하면 버린다.

### 3-3. 실시간 vs 면접 후

| 언제 | 어디서 | 무엇을 | 누가 쓰나 |
|---|---|---|---|
| 면접 중 (실시간) | 브라우저 | MediaPipe 시선·표정, VAD(말하는 중인지) | 지웅(반응 로직), 나 |
| 면접 후 | 서버 | STT 단어 시각, 속도·군말·말투, 음성 분석, 장면 피드백 | 나 → 리포트 화면 |

피드백은 리포트용이라 **면접 후 처리**로 충분하다. 실시간으로 뽑는 신호는 반응 로직과 함께 쓸 수 있으니 형식을 맞춘다.

## 5. 주의할 점

- **측정 정확도 ≠ 평가 타당성**: 시선을 정확히 재도 "시선이 좋다"가 실제 면접 결과와 연결되는지는 별개다. 그래서 단정 대신 **관찰 + 제안**으로 말한다.
- **사람마다 다르다**: 평소 말 속도, 시선 습관, 음높이가 다르다. 절대 기준보다 **본인 기준값 대비 변화**를 본다.
- **환경에 민감하다**: 조명, 안경, 카메라 위치, 마이크 잡음. 면접 전에 짧은 점검 단계를 둔다.
- **얼굴 영상은 개인정보다**: 가능한 한 브라우저에서 처리하고 숫자만 저장한다. 영상을 저장한다면 보관 기간과 동의를 정한다.
