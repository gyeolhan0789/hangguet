A301 · 에이전트 · Egress 오토스케일링 계획 3장

ASG를 넣은 뒤의 운영 구조

면접관 에이전트와 녹화(Egress)를 메인 서버에서 떼어 우리 AWS 계정의 Auto Scaling Group 두 개로 옮긴 모습입니다. 메인 서버에는 LiveKit과 웹 · DB · 큐 · AI 작업자가 남습니다.

다음 릴리즈에는 넣지 않음 · 운영 반영 순서는 계획 10.1

메인 서버에 남는 것 · 빠지는 것

  • 남음: LiveKit · TURN, Nginx(443 입구 · HTTPS) · FE · BE, PostgreSQL · Redis, AI 작업자 3개(질문 생성 · 채점 · 녹화 합치기), 모니터링
  • 빠짐: a301-prod-ai-agent, a301-prod-egress. 지우지 않고 프로필로 꺼 두었다가 되돌릴 때 켭니다
  • 메인 서버는 여전히 단일 장애점입니다. LiveKit · Redis · BE가 이 한 대에 있습니다

세 가지 연결

  • Tailscale: 7880 시그널링, 6379 Redis(비밀번호 필수), 9090 · 3100 지표 · 로그. 태그 tag:a301-agent · tag:a301-egress만 메인 서버로 들어갑니다
  • 공인 IP: UDP 7882 미디어. 사설 IP로 고정하면 TURN으로 들어오는 브라우저가 연결되지 못했습니다
  • S3 게이트웨이 엔드포인트: Egress 업로드가 VPC 안으로 가서, 녹화 키를 IP 대신 aws:SourceVpc 조건으로 묶습니다

대당 면접은 추정입니다. 테스트 서버 3단계에서 확정합니다.

새 버전 반영

  1. master 병합 → prod-build가 ai-<SHA> 이미지를 Docker Hub에 올립니다
  2. prod-deploy ▶로 메인 서버를 먼저 바꿉니다
  3. SSM의 에이전트 이미지 태그를 같은 SHA로 바꿉니다
  4. 에이전트 ASG 인스턴스를 새로 고칩니다. 새 대가 먼저 뜨고, 옛 대는 면접을 마친 뒤 내려갑니다

3 · 4번을 빠뜨리면 에이전트만 옛 버전으로 남습니다. Egress는 LiveKit 버전을 올릴 때만 바꿉니다.
