**배운 것 / 정리**
- API 명세를 Swagger(springdoc)로 코드에서 만들면 명세와 실제 응답이 어긋나지 않음
- 오류 응답은 표준 형식(RFC 9457 ProblemDetail)에 `code`를 더해 화면이 `code`로 분기하게 함. 목록은 Spring Data의 `content`·`page` 형식 사용
- PostgreSQL은 제약 위반이 한 번 나면 그 트랜잭션 전체가 실패함 → 하루 한 건인 연습 기록은 예외를 잡지 않고 `ON CONFLICT DO NOTHING`으로 넣어야 함
- ID를 IDENTITY로 만들면 `persist` 시점에 INSERT가 나가서 제약 위반도 그때 바로 발생함
- DB에서 읽은 일시는 UTC 오프셋으로 나옴(같은 시각). 응답의 `+09:00`은 Jackson 시간대 설정이 맡음

**막힌 것 & 해결**
| 문제 | 원인 | 해결 |
|---|---|---|
| CI 목 서버 빌드가 `./gradlew: Permission denied`로 실패 | Windows에서 파일을 복사하며 실행 권한이 빠짐 | `git update-index --chmod=+x`로 실행 권한을 넣어 첫 커밋에 반영, CI와 같은 Linux 이미지에서 확인 후 다시 push |
| Swagger 문서에 오류 응답 스키마의 타입이 빠짐 | OpenAPI 3.1에서는 `type` 대신 `types`로 지정해야 함 | `types`로 지정, 문서 테스트로 확인 |
| Spring 자체 오류(404·405 등)의 안내 문구가 영어 내부 메시지 | Spring 기본 문구를 그대로 내보냄 | 사용자용 한국어 문구로 바꾸고 테스트 추가 |
| 일시를 +09:00으로 읽게 하는 DB 설정이 효과 없음 | Hibernate가 `timestamptz`를 UTC로 읽음 | 설정 제거, 응답 시간대는 Jackson 설정으로 처리 |

### 📅 2026-10-14 (수)

**오늘 한 것**
- 2D 면접관 점 찍어 휘기(mesh warp) 고도화 연구 및 결과 문서화 (S15P31A301-62)
  - 그림에서 얼굴 점 478개를 찾아 점을 옮기며 그림을 휘고 섞는 방식으로 장난꾸러기 악마 구현, 2D 기본 방식으로 결정
  - 움직임 개선: 표정 보간(스프링, 미소 최대 변화 속도 85 → 3.9/s), 발화 종료 시 미소 끊김 수정(표현 모듈, 85 → 2.9/s), 애니메이션 원칙(시차·예고 동작·지나침), 끄덕임 곡선 수정. 단위 테스트 128개 통과
  - 미세 표정 그림 비교(13·18·21장): 8장 중 3장은 점 이동이 1~3px라 효과 없음 → 효과가 확인된 5장만 더한 18장으로 결정(첫 로딩 0.5초)
  - 다른 캐릭터 적용 확인: 개발자 커피챗·실사 면접관·팀장 면접관(확인용)을 같은 코드로 동작 확인. 새 캐릭터는 그림 13장만 새로 그리고 코드 변경 없음
  - GPU 없는 환경 성능 측정: 한 장 그리기 1254px 61ms(초당 16장) → 720px 29ms(초당 34장), 렌더 크기 자동 조정 방안 정리
  - 반응 지연 측정(반응 이벤트 → 화면에 반쯤 보임): 미소 0.34초, 끄덕임 0.15초, 입 0.03초
  - 실사 면접관 움직임 블라인드 비교: 크기 절반·문장 쉼 멈춤은 괜찮음, 질문 끝 직전 깜빡임을 넣은 세 쌍은 모두 평가 하락, 고개 위아래 동작·입 모양 문제 확인
  - 입 모양 고도화(모음별 입)와 지원자 영상 활용(MVP 이후) 계획 수립
  - 검증 결과·결정 변경을 기획 문서에 반영 ([verification.md](interviewer-avatar/verification.md) 9장)
- 팀 공유용 시연 영상·기술 설명 정리

**배운 것 / 정리**
- 2D 그림 면접관은 그림 장수보다 움직임 설계(보간·시차·쉼)와 그림끼리의 일관성(이빨·눈썹·입 벌림 단계)이 자연스러움을 좌우함
- 그림 장수는 첫 로딩에만 영향을 주고(13장 0.4초, 18장 0.5초, 저사양 1.4초·1.8초), 면접 중 그리는 비용은 그 순간 섞이는 그림 수와 그리는 크기로 정해짐
- GPU가 없는 기기에서는 그리는 크기가 부드러움을 결정함: 1254px 초당 12~16장, 720px 초당 30장 이상. 그리는 시간은 픽셀 수에 비례(약 7.5ms + 34ms × 픽셀 수 ÷ 100만)
- 말하는 내내 같은 크기로 움직이면 어색하고, 작게 하거나 문장 쉼에서 멈추면 자연스러워짐. 불규칙한 박자 자체는 효과가 없었음
- 2D에서 얼굴만 위아래로 움직이면 얼굴이 미끄러져 보이고, 그림 전체를 움직이면 화면이 흔들려 보임
- 비교 실험은 무작위 요소(깜빡임 시점)를 고정하고, 조건을 가린 상태로 평가해야 원인을 가릴 수 있음. 한 번에 하나만 바꿔야 함

**막힌 것 & 해결**
| 문제 | 원인 | 해결 |
|---|---|---|
| 발화가 끝날 때 미소가 뚝 끊김 | 상태 전환 시 순간 표정을 즉시 삭제 | 현재 세기에서 0.5초에 걸쳐 내려가도록 수정 |
| 그림 가장자리에 흰색·하늘색 테두리 | 그림 생성 도구가 반투명 가장자리에 밝은 색을 섞음 | 가장자리 띠를 안쪽 색으로 바꾸고 알파를 깎는 처리를 모든 그림에 적용 |
| 말할 때 이빨 크기가 커졌다 작아졌다 함 | 입 그림마다 이빨을 별도로 그림 | '아' 입 이빨에 맞춰 입 그림을 다시 그림 |
| 끄덕일 때 얼굴이 머리카락 안에서 미끄러짐 | 끄덕임 크기를 2D가 감당 못 함 | 2D 끄덕임에 부드러운 상한 적용 |
| 하관만 움직이는 느낌 | 그림의 눈썹이 입·미소와 함께 움직이지 않음 | 말할 때 강세에 맞춰 눈썹·입꼬리를 코드로 움직임 |
| 같은 조건인데 영상마다 평가가 다름 | 깜빡임 시점이 녹화마다 무작위 | 난수를 고정하고 블라인드 비교로 다시 확인 → 질문 끝 직전 깜빡임이 원인 |
| 실사 면접관의 말하는 입이 실제 음량보다 작게 열림 | 입을 거의 안 벌린 '오'·'에' 그림이 섞임 | 원인 확인. 여러 수정을 한 번에 넣어 실패 → 검증된 상태로 되돌리고 미해결 과제로 정리 |

**배운 것 / 정리**
- 렌더러 비교: 자체 컨트롤러가 120fps·번들 +7kB로 TalkingHead(최대 72fps·+226kB)보다 가볍고, TalkingHead의 자동 대기 동작·표정은 우리 동작 층 구조와 충돌
- 립싱크: HeadAudio는 영어 학습 모델이라 한국어 "아"를 한 번도 `viseme_aa`로 분류하지 못함 → MVP는 음량 기반, HeadAudio는 2차
- 2D 그림 면접관: 새 내용(감은 눈·벌린 입)은 코드로 지어낼 수 없고 그린 그림이 필요. 눈·입 그림은 기본 그림과 실제로 달라지는 영역만 남겨야 표정 그림 위에 겹쳐도 티가 나지 않음
- 시험(spike) 결과물 관리: 결과와 근거는 문서로 남기고, 시험 코드는 핵심만 발췌하며 제품 코드로 복사하지 않음
- 라이선스: MakeHuman 에셋 CC0, TalkingHead MIT, Windows 기본 음성은 배포 불가. MetaHuman은 다른 엔진 사용이 허용됐지만 AI 학습·개선에는 사용 불가
