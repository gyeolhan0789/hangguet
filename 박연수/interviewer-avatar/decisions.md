# 면접관 표현 모듈: 결정 사항

[← 개요](overview.md)

## MVP 기준

> 면접관이 질문을 **발화**하고, 사용자 발화 중 **경청**하며, 발화 종료 후 **생각** 상태로 전환되는 흐름을 완성한다. 그 외 기능은 고도화 단계에서 확장한다.

**MVP 완료 기준**: 질문 Text 입력 시 3D 면접관이 음성과 립싱크로 발화하고, 사용자 발화 시 listening, 발화 종료 시 thinking으로 전환된다.

## ① 음성 합성 (TTS)

| # | 항목 | MVP | 고도화 |
|---|---|---|---|
| ①-1 | TTS 선정 | **GMS TTS**, 미제공 시 브라우저 TTS | 입 모양 정보(Viseme) 제공 TTS 비교 |
| ①-2 | 음성 스타일 | **고정**: 차분한 어조, 보통보다 약간 느린 속도 | 질문·안내·종료별 억양 구분 |
| ①-3 | TTS 실패 처리 | **질문 Text만 표시** | 브라우저 TTS 자동 전환 |

- GMS TTS 사용 불가 시 음성 데이터를 제공하는 대안 TTS를 탐색한다.
  - 1차 대안: [Google Cloud TTS Chirp 3: HD](https://docs.cloud.google.com/text-to-speech/docs/chirp3-hd?hl=ko) (한국어 지원, 음성 데이터 반환, 스트리밍 합성 지원, 비용 확인 필요)

## ② 립싱크

| # | 항목 | MVP | 고도화 |
|---|---|---|---|
| ②-1 | 동기화 방식 | **음량 기반** 입 벌림 조절 | 모음별 입 모양 구분 (Viseme) |

- 음량 기반 방식은 음성 데이터를 제공하는 TTS(GMS TTS 등)에 적용할 수 있으며, 모음별 입 모양은 구분하지 못한다.
- 브라우저 TTS는 음성 데이터를 제공하지 않아 음량 기반 방식을 적용할 수 없으므로, 발화 시작·종료 이벤트 기반 입 애니메이션으로 대체한다.

## ③ 면접관 렌더링

| # | 항목 | MVP | 고도화 |
|---|---|---|---|
| ③-1 | 렌더링 방식 | **3D (VRM + Three.js)** | — |
| ③-2 | 면접관 모델 | **무료 VRM 모델** (사용 범위 확인) | 자체 제작·수정 |
| ③-3 | 3D 실패 처리 | **정지 이미지** | 2D 캐릭터 (Live2D) |
| ③-4 | 표정·제스처 | **표정 2종**(기본, 경청) + **끄덕임 1종** | 표정 5종, 제스처 4종 |

- 3D 선정 사유: 고개·시선·상체를 함께 표현할 수 있고, VRM 표준을 따르므로 모델 교체 시 코드 변경이 적다.
- AI 기반 얼굴 영상 생성(Audio2Face, MuseTalk 등)은 GPU 서버가 필요하고 턴별 지연이 커 MVP 범위에서 제외한다.

## 진행 순서

1. ①-1: GMS TTS 확인, 사용 불가 시 대안 TTS 탐색 (1차 대안: Chirp 3: HD)
2. ②-1: 정지 이미지 + GMS TTS + 음량 기반 립싱크로 1차 연동
3. ③-1, ③-2: VRM 모델 적용

결정 사항 변경 시 본 문서와 [개요](overview.md)의 해당 항목을 함께 수정한다.
