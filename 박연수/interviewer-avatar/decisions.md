# 면접관 표현 모듈: 결정 사항

[← 개요](overview.md)

## MVP 기준

> 면접관이 질문을 **발화**하고, 사용자 답변 중 **경청**하며 반응하고, "답변 완료" 후 **생각** 상태로 전환되는 흐름을 완성한다. 그 외 기능은 고도화 단계에서 확장한다.

**MVP 완료 기준**: 질문 Text와 음성 URL을 받으면 면접관이 음성과 립싱크로 발화하고, 발화가 끝나면 listening, "답변 완료" 시 thinking으로 전환되며, 반응 이벤트에 따라 표정·제스처가 바뀐다.

프로토타입으로 아래 결정을 검증했다. 근거와 수치는 [verification.md](verification.md).

## ① 음성 합성 (TTS)

| # | 항목 | MVP | 고도화 |
|---|---|---|---|
| ①-1 | TTS 선정 | **Chirp 3: HD** (Google Cloud TTS) | 입 모양 정보(Viseme) 제공 TTS 비교 |
| ①-2 | 음성 스타일 | **페르소나별** 톤·속도 (예: 악마 면접관 낮은 톤 1.05배) | 질문·안내·종료별 억양 구분 |
| ①-3 | TTS 실패 처리 | **질문 Text만 표시** (TTS 실패·Timeout, 음성 로드 실패 포함) | 브라우저 TTS 자동 전환 |
| ①-4 | 질문 표시 | **음성·글·둘 다 3가지 모드**. 화상·채팅 모두 음성 + 말풍선(둘 다) | 음성에 맞춘 자막 |

- TTS는 BE 요청으로 AI 파트에서 호출하며, FE는 TTS Provider Credential을 보유하지 않는다 ([CONTRIBUTING.md](../../docs/CONTRIBUTING.md) 2.2, 6.1, 7장, 구조는 [architecture.md](architecture.md) 1장).
- Windows 기본 음성(Heami)은 로컬 테스트 전용이며 배포에 쓰지 않는다.

## ② 립싱크

| # | 항목 | MVP | 고도화 |
|---|---|---|---|
| ②-1 | 동기화 방식 | **음량 기반** `jawOpen` (상한 0.55) | 모음별 입 모양: 질문 글자 + 음량 → 강제 정렬로 보정 → 필요 시 발음 시각 TTS ([verification.md](verification.md) 9.11절) |

- 영어 학습 모델인 HeadAudio는 한국어 모음을 잘못 분류해 2차로 미뤘다 ([verification.md](verification.md) 2.2절).
- 립싱크 보간(열림 50ms, 닫힘 120ms)은 면접관 표현 모듈 한 곳에서만 한다.

## ③ 면접관 렌더링

| # | 항목 | MVP | 고도화 |
|---|---|---|---|
| ③-1 | 렌더링 방식 | **2D 점 찍어 휘기(mesh warp)** (10/14 변경, 이전: 표정 그림 바꿔 끼우기). 3D(자체 three.js 컨트롤러 + GLB)는 대안 중 하나로 둠 | 실사 그림 (협의 후 확정) |
| ③-2 | 면접관 모델 | **페르소나별 2D 그림 18장** (기본 13장 + 미세 표정 5장, Codex 생성) (10/14 변경, 이전: GLB 2종 + 그림 25장) | 모음별 입 그림 8장 |
| ③-3 | 실패 처리 | **정지 이미지** (WebGL 미지원·로드 실패·10초 Timeout·컨텍스트 손실). **렌더 크기 자동 조정**: 화면 표시 크기 × 기기 배율, 느리면 단계적으로 낮춤 | 실제 저사양 기기 기준 단계 조정 |
| ③-4 | 표정·제스처 | **기본 구성**: 태도 2종(관심·무덤덤) + 순간 표정 3종(미소·찌푸림·히죽) + 제스처 3종(작은 끄덕임·끄덕임·갸웃). 어떤 반응을 언제 보일지는 반응 로직 모듈이 판단 | 굳음·기다림, 끼어들기 |

- **10/14 변경**: 2D 면접관을 점 찍어 휘기로 바꾸고 페르소나 3종 모두 2D로 시작한다. 같은 코드로 캐릭터를 추가할 수 있고, 표정 세기를 연속으로 조절하며, GPU가 없어도 화면 크기로 그리면 초당 30장 이상 나온다(근거·남은 과제는 [verification.md](verification.md) 9장). 악마 면접관에 실사 그림을 쓸지는 협의 후 확정한다.
- 외형은 실사에 가까운 사람 모습을 우선한다(검토한 대안과 탈락 이유는 [verification.md](verification.md) 2.5절). 그래서 VRM(애니메이션풍) 대신 GLB(Mixamo 호환 뼈대 + ARKit 표정 52종 + Oculus 입 모양 15종)를 쓴다.
- TalkingHead는 대기 동작·기분 표정이 우리 동작 층 구조와 충돌해 쓰지 않는다. 팔 내림 대기 자세는 코드로 구현한다.
- Mixamo 애니메이션은 웹 배포 시 원본 재배포 문제가 있어 쓰지 않고, 제스처는 코드로 만든다.
- ③-4 반응 구성과 수치는 기본안이며, 구현·테스트 단계와 배포 이후 사용 데이터 분석 단계에서 구체화할 수 있다.
- 시선은 카메라 고정, 머리카락 물리는 없다.
- AI 기반 얼굴 영상 생성(Audio2Face, MuseTalk 등)과 실시간 실사 아바타 서비스는 GPU 서버 또는 사용 시간 과금이 필요해 MVP 범위에서 제외한다.

## 진행 순서

브랜치 순서는 문서 정정 → 모듈 세팅 → CI → 반응 이벤트 계약(common) → 렌더러 기반 → TTS(AI) → 음성 재생 → 상태·제스처 → 태도 표정 → 음성 연동 → 성능 측정이다. 구현할 때는 [spike/](spike/README.md)의 핵심 코드와 [verification.md](verification.md)를 참고한다.

결정 사항 변경 시 본 문서와 [개요](overview.md), [검증 결과](verification.md)의 해당 항목을 함께 수정한다.
