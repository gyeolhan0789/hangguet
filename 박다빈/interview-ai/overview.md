# 내 담당: 질문 생성 · 답변 평가

> 이 회사 면접에서 나올 질문을 만들고, 사용자의 답이 이 회사에 맞는지 채점한다.

정해야 할 것 목록: [decisions.md](decisions.md) · 아키텍처와 고도화 계획: [architecture.md](architecture.md)

## 1. 하는 일 (3단계)

| 단계 | 하는 일 | 예시 |
|---|---|---|
| ① 회사 자료 모으기 | 공시·뉴스·채용 페이지를 모아 회사 요약 카드를 만든다 (데이터 분산처리) | "○○사는 협업을 중시하고, 요즘은 수익화에 집중한다" |
| ② 질문 만들기 | 요약 카드 + 공고 + 이력서로 예상 질문과 꼬리질문을 만든다 | "기존 서비스를 개선해 본 경험이 있나요?" |
| ③ 답변 채점하기 | 답변을 요약 카드와 비교해 회사에 맞는지 판정하고 고칠 점을 알려준다 | "이 회사는 수익화를 중시해요. '도전'보다 기존 서비스를 키운 경험으로 말해 보세요." |

**담당 아님**: 면접관 영상, 표정·시선 분석, 화면 개발

## 2. ① 회사 자료 모으기

### 수집 대상
| 자료 | 경로 | 비고 |
|---|---|---|
| 공시 (사업보고서) | DART OpenAPI | 무료, 일일 호출 한도 있음 |
| 뉴스 | 네이버 뉴스 검색 API, 빅카인즈 | 제목·요약·링크만 저장 (본문 저장 X) |
| 인재상·채용공고 | 기업 채용 페이지 | robots.txt 준수 |

잡플래닛·블라인드 리뷰는 수집하지 않는다 (이용약관상 크롤링 금지).

### 처리 흐름
```
수집 (Kafka · Airflow) → 원본 저장 (MinIO)
  → 정제 (Spark: 파싱 · 중복 제거 · 기업명 매칭 · 중요도 필터)
  → 요약 (LLM: 회사 요약 카드, 출처 포함)
  → 저장 (pgvector)
```
서버: 추가 EC2 c6g.2xlarge + EBS 60GB (교보재 신청함)

### 결과물: 회사 요약 카드
```json
{
  "corp_code": "00000000",
  "name": "○○사",
  "talent": [{"keyword": "협업", "source": "채용 페이지 URL"}],
  "direction": [{"summary": "기존 서비스 안정화와 수익화에 집중", "source": "2025 사업보고서"}],
  "recent_issues": [{"summary": "결제 플랫폼 리뉴얼 발표", "date": "2026-09-30", "source": "기사 링크"}],
  "job_skills": [{"summary": "대용량 트래픽 · 장애 대응 경험", "source": "채용 공고"}]
}
```

## 3. ② 질문 만들기

- 입력: 회사 요약 카드 + 채용공고 + (선택) 이력서
- 출력: 예상 질문 6~8개, 질문마다 유형(인성·경험·직무·회사)과 근거 항목
- 꼬리질문: 면접 중 답변을 받아 1개씩 추가 생성

```json
{
  "question_id": "q3",
  "text": "트래픽이 몰려 장애가 났던 경험을 이야기해 주세요.",
  "type": "경험",
  "basis": "job_skills"
}
```

## 4. ③ 답변 채점하기

### 평가 항목
| 항목 | 잘 맞음 | 보완 필요 | 어긋남 |
|---|---|---|---|
| 인재상 부합 (회사) | 인재상에 맞는 행동이 사례로 드러남 | 방향은 맞지만 사례가 없음 | 인재상과 반대되는 태도 |
| 사업·직무 연결 (회사) | 경험을 회사 사업·직무와 연결함 | 연결 시도는 있으나 일반론 | 회사 방향과 반대 |
| 질문 의도 (기본) | 물어본 것에 답함 | 일부만 답함 | 다른 이야기 |
| 구체성 (기본) | 내 역할·행동·결과가 분명 | 일부 빠짐 | 추상적 표현뿐 |

### 규칙
- 근거 자료가 없으면 그 항목은 "판단 보류"
- 최종 판정: 회사 항목 중 하나라도 "어긋남" → 어긋남 / 아니면 "보완 필요"가 있으면 → 보완 필요 / 나머지 → 잘 맞음
- 피드백: 가장 중요한 지적 1개 + 근거(요약 카드 원문 인용) + 고쳐 말할 예시 1문장
- 인용 문장이 원문에 없으면 그 피드백은 버린다 (지어내기 방지)

### 출력 예시
```json
{
  "question_id": "q3",
  "verdict": "보완 필요",
  "scores": {"talent_fit": "잘 맞음", "business_fit": "보완 필요", "intent": "잘 맞음", "specificity": "보완 필요"},
  "feedback": {
    "point": "결과가 '설정을 바꿨다'에서 끝나요. 재발을 막기 위해 무엇을 바꿨는지가 빠졌어요.",
    "evidence": [{"card_field": "direction", "quote": "기존 서비스 안정화와 수익화에 집중", "source": "2025 사업보고서"}],
    "rewrite": "설정을 바꾼 뒤, 같은 문제가 다시 생기지 않도록 알림 기준과 점검 절차를 팀과 함께 만들었습니다."
  }
}
```

## 5. 팀원과 맞출 것

| 주고받는 것 | 상대 | 형식 |
|---|---|---|
| 질문 → 면접 화면 (TTS·자막) | 면접 화면 담당 | 3장 질문 JSON |
| 답변 텍스트 ← STT | 음성 담당 | 협의 필요 |
| 채점 결과 → 리포트 화면 | 프론트 담당 | 4장 출력 JSON |
