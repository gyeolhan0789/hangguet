# AI·미디어 서버 분리 계획

서버 한 대에서 BE·AI·LiveKit·Egress를 별도 프로그램으로 실행한다. 아래는 분리 방향이며, 구현·폐기 상태는 API 변경 열에 구분한다.

## 서버별 역할

| 구성 | 담당 기능 | 코드 위치 |
| --- | --- | --- |
| BE | 업무 API, DB 저장, AI 작업 요청·결과 수신, 면접방·녹화 제어 | `backend/` |
| AI 에이전트 | Soniox 음성 인식·화면 텍스트 전달, ElevenLabs 질문 음성(첫 질문). Jev 반응·면접 진행은 예정 | `ai/app/agent/`(실행 진입점), `ai/app/interview/realtime/` |
| AI 생성·평가 | GMS 호출로 질문 생성·답변 채점·종합 평가, 말하기 분석, 녹화 트랙 합치기. 에이전트와 별도 실행 | `ai/app/worker/`(실행 진입점), `ai/app/interview/`(realtime 제외), `ai/app/recording/`(예정) |
| LiveKit | 화면과 에이전트의 음성·영상·메시지 중계 | 배포 설정 |
| Egress | 지원자 영상·음성 녹화 | 배포 설정 |

AI에 업무 HTTP API를 추가하지 않는다. BE와 AI는 Redis로 작업·결과를 전달하며, DB 저장은 BE가 담당한다.

## BE와 AI가 주고받는 내용

| 방향 | 내용 | 수단 |
| --- | --- | --- |
| BE → AI 생성·평가 | 자소서·질문·답변과 생성·채점 요청 | Redis 작업 큐 |
| AI → BE | 생성·평가 결과, 질문 시작·인식한 화상 답변, 진행·실패 상태 | Redis 결과 큐 |
| BE → 에이전트 | 면접 시작에 필요한 질문·설정 | LiveKit 에이전트 배정 정보 |
| BE → 에이전트 | 답변 저장 성공·다음 질문 진행 통지 | 방식 확정 필요 |

GMS·Jev는 AI의 파이썬 코드에서 직접 호출하고 키는 AI 환경변수로 받는다. AI에는 작업 수신·결과 전송, 답변 종료 판단·시간 제한, 말하기 지표 계산, 재연결·재시도·중복 처리도 구현한다. 기존 `/health` 외에 새 업무 HTTP API를 추가할 계획은 없다.

## 분리에 따른 API 변경

| 기존 API | 분리 후 처리 | API 변경 |
| --- | --- | --- |
| 5.1·5.3 면접 생성·질문 재생성 | BE가 요청하고 AI가 질문 생성 | 경로 변경 없음. AI 처리 연결 |
| 5.4 면접 시작 | BE가 LiveKit 입장 정보 발급·에이전트 배정·녹화 시작 | 응답에 입장 정보 추가 |
| 5.7 채팅 답변 | BE가 저장하고 AI에 채점 요청·에이전트에 다음 질문 진행 통지 | 채점 요청·저장 성공 통지 연결 |
| 5.8 면접 종료 | BE가 방·녹화를 종료하고 AI에 종합 평가 요청 | 평가 요청·녹화 제어 연결 |
| 5.9 결과 재생성 | BE가 요청하고 AI가 평가 | 경로 변경 없음. AI 처리 연결 |
| 5.10 STT 토큰 | 에이전트가 Soniox에 직접 연결 | BE·목 서버에서 폐기 완료 |
| 5.11 반응 요청 | 에이전트가 처리해 LiveKit 메시지로 전달 | 대체 검증 후 폐기 |
| 5.12 TTS 토큰 | 에이전트가 ElevenLabs REST로 합성해 면접방에 송출 | BE·목 서버에서 폐기 완료. 에이전트 TTS 구현 |
| 5.14 면접방 입장 토큰 | BE가 입장·재입장 토큰 발급 | BE·목 서버 추가, 프론트 연결 완료 |
| 6.1·6.2 녹화 업로드·등록 | Egress가 녹화하고 BE가 완료 확인·등록 | 대체 검증 후 폐기 |
