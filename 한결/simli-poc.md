## 1. 구현 방식

| 구분 | 구현 내용 |
| --- | --- |
| 기술 스택 | React(Vite), Node.js(Express), Simli JS SDK |
| 아바타 | Simli Legacy 기반 2D 실사형 면접관 |
| 영상 연결 | LiveKit을 활용한 실시간 스트리밍 |
| 한국어 립싱크 | MP3/WAV 음성을 16kHz PCM16으로 변환 후 Simli에 전달 |
| 반응 구현 | IDLE, NOD, TILT, FROWN 영상 전환 |
| 영상 전환 | 크로스페이드 적용, 반응 종료 후 IDLE 복귀 |
| API 키 관리 | 서버 `.env`에 저장하고 세션 토큰으로 연결 |

### 주요 구현 사항

- 립싱크: Simli를 활용해 한국어 음성에 맞춰 입이 움직이는 2D 실사형 AI 면접관 구현
- 반응 시스템: AI 이벤트에 따라 미리 제작된 반응 영상을 재생할 수 있는 구조 구현. 실제 AI 이벤트 연동은 미완료
- TTS 연동: GMS 기반 TTS 연동 코드 작성 완료. API 키 미발급으로 실제 테스트는 미진행
- 테스트 방식: 한국어 MP3/WAV 음성 파일을 활용해 립싱크 검증
- 미완성 부분: 반응 영상은 테스트용 이미지 기반이며, 실제 인물 영상 제작 및 AI 이벤트 연동 필요

## 2. 테스트 결과

아래 내용은 이번 PoC 환경에서 관찰한 결과이며, 타이밍과 자연스러움은 정량 측정이 아닌 정성 평가이다. API 기능과 무료 플랜 제약도 테스트 당시 사용 환경을 기준으로 기록한다.

| 항목 | 결과 |
| --- | --- |
| 한국어 립싱크 | 정상 동작 |
| 음성과 입의 타이밍 | 대체로 일치 |
| 입 모양의 자연스러움 | 부족 |
| fasttalk vs artalk | artalk가 소폭 우세 |
| 반응 영상 전환 | 정상 동작 |
| 실제 인물 반응 영상 | 미구현 |
| GMS TTS 연동 | 미검증 |

### 확인된 문제점

1. 립싱크의 자연스러움 부족
   - 음성과 입의 타이밍은 맞지만 입 모양이 단조로움
   - 입을 크게 벌리거나 오므리는 동작이 부족해 웅얼거리는 느낌이 발생
   - 팀원이 구현한 VRM 3D 모델보다 립싱크가 부자연스럽게 보임
2. 표정 및 동작 제어의 한계
   - 사용한 Simli API에서 입 움직임의 크기를 직접 조절하지 못함
   - 끄덕임, 갸웃, 찌푸림 등의 반응을 실시간으로 직접 제어하지 못함
   - 별도 반응 영상을 제작하고 전환해야 하며, 현재 구현에서는 말하는 중에 반응을 표시하지 못함
3. 외부 API 의존성
   - 테스트 당시 무료 플랜에서 최신 Trinity 얼굴을 사용하지 못함
   - 사용한 무료 플랜의 동시 연결은 1개로 제한됨
   - 네트워크 및 API 사용량에 따른 제약 존재

## 3. 최종 결론

Simli를 활용해 2D 실사형 AI 면접관의 한국어 립싱크와 반응 영상 전환 기능을 구현했으나, 입 모양이 단조롭고 실시간 표정 제어가 어려워 자연스러움에 한계가 있음을 확인했다.

따라서 v1에서는 이번 비교에서 립싱크와 반응 제어가 상대적으로 우수했던 3D VRM 방식을 우선 적용하고, Simli는 추후 Trinity 모델의 품질을 검증한 뒤 재검토할 예정이다.
