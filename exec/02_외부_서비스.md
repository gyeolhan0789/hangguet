# 한끗 포팅 매뉴얼 2. 외부 서비스

프로젝트에서 사용하는 외부 서비스와, 새로 가입해 같은 환경을 만들 때 필요한 설정을 정리한 문서입니다.
빌드 · 배포 방법과 전체 환경 변수 목록은 [01_빌드_배포_매뉴얼.md](01_빌드_배포_매뉴얼.md)에 있습니다.

- 이 문서에는 **키 값을 적지 않습니다.** 발급받은 값은 GitLab > Settings > CI/CD > Variables에 각 항목의 「변수」 이름으로 등록합니다(Protected · Masked).
- 브라우저는 외부 API를 직접 호출하지 않으며, 키는 모두 서버(BE · AI)에만 있습니다. 예외는 카카오 인가 화면으로 이동할 때 쓰는 `KAKAO_CLIENT_ID`(공개되어도 되는 값) 하나입니다.
- 외부 콘솔의 메뉴 이름은 서비스 개편에 따라 문서와 조금 다를 수 있습니다.

## 2. 소셜 로그인 · 알림 · 메일

### 2.1 카카오(로그인 · 카카오톡 연습 알림)

[Kakao Developers](https://developers.kakao.com)에서 애플리케이션을 하나 만들고, 로그인과 연습 알림에 같은 앱을 씁니다.

사용하는 API는 다음과 같습니다.

- 로그인: 인가 코드 받기(`kauth.kakao.com/oauth/authorize`) → 토큰 받기(`/oauth/token`) → 사용자 정보 조회(`kapi.kakao.com/v2/user/me`)
- 연습 알림: 동의 항목 조회(`/v2/user/scopes`), 나에게 보내기(`/v2/api/talk/memo/default/send`)

콘솔에서 설정할 항목은 다음과 같습니다.

| 항목 | 값 |
|---|---|
| 앱 키 | **REST API 키**를 `KAKAO_CLIENT_ID`로 등록합니다 |
| 플랫폼 > Web 사이트 도메인 | `https://hangguet.co.kr`(로컬에서 확인하려면 `http://localhost:3000`도 추가) |
| 카카오 로그인 | 활성화 |
| Redirect URI | `https://hangguet.co.kr/oauth/kakao/callback` |
| 보안 > Client Secret | 발급 후 활성화하고 `KAKAO_CLIENT_SECRET`으로 등록합니다. 쓰지 않는다면 변수를 비워 둡니다 |
| 동의 항목 | 닉네임, 카카오계정(이메일), **카카오톡 메시지 전송(`talk_message`)** |

주의할 점은 다음과 같습니다.

- Redirect URI는 카카오 콘솔, BE의 `KAKAO_REDIRECT_URIS`, FE의 `KAKAO_REDIRECT_URI` 세 곳이 **글자 하나까지 같아야** 합니다. 뒤의 두 값은 `deploy/prod/compose.yml`에 있습니다.
- BE는 **유효하고 인증된 이메일**만 사용합니다. 이메일 동의 항목을 설정하지 않으면 가입 정보에 이메일이 비어서 들어옵니다.
- `talk_message` 동의는 로그인할 때가 아니라 사용자가 연습 알림을 켤 때 따로 받습니다. 이때 FE가 `scope=talk_message`를 붙여 인가 화면을 다시 엽니다.
- 관련 코드: BE `auth/oauth/KakaoLoginClient.java` · `alarm/kakao/KakaoMessageClient.java`, FE `src/lib/auth/kakao.ts`

### 2.2 구글 OAuth

[Google Cloud Console](https://console.cloud.google.com)의 API 및 서비스 > 사용자 인증 정보에서 OAuth 클라이언트 ID(유형: 웹 애플리케이션)를 만듭니다. BE는 토큰 받기(`oauth2.googleapis.com/token`)와 사용자 정보 조회(`openidconnect.googleapis.com/v1/userinfo`) API를 사용합니다.

| 항목 | 값 |
|---|---|
| OAuth 동의 화면 | 앱 이름과 지원 이메일을 등록하고, 범위는 `email` · `profile`을 선택합니다 |
| 승인된 리디렉션 URI | `https://hangguet.co.kr/oauth/google/callback` |
| 클라이언트 ID / 보안 비밀번호 | `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`으로 등록합니다. 두 값이 모두 있어야 합니다 |

- 리디렉션 URI는 BE의 `GOOGLE_REDIRECT_URIS`(`compose.yml`)와 같아야 합니다.
- 현재는 BE API(`POST /api/v1/auth/oauth/google`)만 구현되어 있고, 사용자 화면에는 구글 로그인 버튼과 콜백 경로가 없습니다. 그래서 운영 서비스에서는 카카오 로그인만 쓰며, 구글 키가 없어도 서비스 이용에는 영향이 없습니다.
- 관련 코드: BE `auth/oauth/GoogleLoginClient.java`

### 2.3 Gmail SMTP(비밀번호 찾기 메일)

발송용 Google 계정에서 2단계 인증을 켠 뒤 [앱 비밀번호](https://myaccount.google.com/apppasswords)(16자리)를 만듭니다. BE는 `smtp.gmail.com:587`에 STARTTLS로 접속합니다(`application.yml`의 `spring.mail`).

| 변수 | 값 |
|---|---|
| `MAIL_USERNAME` | Gmail 주소. 보내는 사람 주소로도 씁니다 |
| `MAIL_PASSWORD` | 앱 비밀번호(계정 비밀번호가 아닙니다) |
| `PASSWORD_RESET_URL` | `https://hangguet.co.kr/password-reset`. 메일 속 링크가 여는 화면으로, `compose.yml`에 적혀 있습니다 |

메일 계정이 없으면 메일을 보내지 않고 경고 로그만 남깁니다. 메일 서버 연결은 서비스 상태 확인 항목에 넣지 않았으므로, 메일 문제로 배포 확인이 실패하지는 않습니다.

### 2.4 Google Forms(설문, 선택)

성장 리뷰 화면에 띄우는 설문 링크입니다. FE를 빌드할 때 `NEXT_PUBLIC_SURVEY_URL`에 폼 주소를 넣으면 설문 버튼이 나오며, 주소 안의 `{userId}` · `{streak}` 자리에는 회원 번호와 연속 연습 일수가 채워집니다. 값을 넣지 않으면 버튼이 나오지 않습니다.

## 3. AI

AI 관련 외부 서비스는 모두 AI 서버(에이전트 · 분석 작업자)에서만 호출합니다. 키는 GitLab 변수 범위를 All로 등록하며, 개발 서버와 운영 서버가 같은 키를 씁니다.

### 3.1 Soniox(실시간 STT)

| 항목 | 내용 |
|---|---|
| 가입 | [Soniox](https://soniox.com) 콘솔에서 프로젝트를 만들고 API 키를 발급해 `SONIOX_API_KEY`로 등록합니다 |
| 연결 | `wss://stt-rt.soniox.com/transcribe-websocket`(WebSocket). 에이전트가 답변마다 새로 연결합니다 |
| 모델 | `stt-rt-v6`(`SONIOX_STT_MODEL`로 바꿀 수 있습니다) |
| 관련 코드 | `ai/app/agent/stt.py` |

- **계정당 실시간 동시 연결은 10개까지입니다.** 그래서 BE의 화상 면접 동시 진행 상한(`INTERVIEW_MAX_VIDEO`)을 운영 8개, 개발 2개로 나눠 두었습니다. 계정 한도가 다르다면 이 값도 함께 조정합니다.
- 키가 없으면 에이전트가 기동하지 않습니다.

### 3.2 ElevenLabs(TTS)

| 항목 | 내용 |
|---|---|
| 가입 | [ElevenLabs](https://elevenlabs.io)의 API Keys 메뉴에서 키를 발급해 `ELEVENLABS_API_KEY`로 등록합니다 |
| API | `POST api.elevenlabs.io/v1/text-to-speech/{voice_id}/with-timestamps` |
| 모델 · 출력 | `eleven_multilingual_v2`, `pcm_24000` |
| 관련 코드 | `ai/app/agent/tts.py` |

- 면접관 3명(악마 · 커피챗 · 오리)의 음성 ID는 `ai/app/agent/tts.py`의 `VOICE_IDS`에 적혀 있습니다. **새 계정에서 이 음성 ID를 사용할 수 있는지 먼저 확인하고**, 다른 음성을 쓰려면 이 값을 바꿉니다.
- 키가 없으면 면접관 음성 없이 질문을 글로만 보여 줍니다.
- 오리 면접관의 칭찬 음성은 미리 합성해 저장소(`ai/app/agent/duck_praise/`)에 넣어 두었으므로, 면접 중에는 API를 호출하지 않습니다.

### 3.3 Jev(면접관 반응 · 인상 판단 · 자기소개서 검증)

| 항목 | 내용 |
|---|---|
| API | `POST https://api.typesafe.ai/v1/systemone` |
| 키 | Jev 제공사(Typesafe)에서 발급받은 API 키를 `JEV_API_KEY`로 등록합니다. Jev SDK 예제의 `TYPESAFE_API_KEY`와 같은 값입니다 |
| 관련 코드 | `ai/app/agent/jev.py` · `impression.py`, `ai/app/interview/cover_letter.py` |

사용하는 곳은 두 군데입니다.

- 에이전트: 답변을 듣는 동안 면접관 반응(끄덕임 · 갸웃)을 판단하고, 카메라 사진으로 인상을 판단합니다.
- 분석 작업자(`ai-analysis`): 지원서를 저장하기 전에 자기소개서를 검증합니다.

키가 없어도 면접은 반응 없이 진행되지만, **자기소개서 검증이 모두 실패해 지원서를 저장할 수 없습니다.** 서비스 전체 흐름을 쓰려면 사실상 필수입니다.

### 3.4 SSAFY GMS(LLM)

SSAFY가 교육생에게 제공하는 LLM 게이트웨이입니다. 발급받은 GMS 키를 `LLM_API_KEY`로 등록합니다.

| 항목 | 내용 |
|---|---|
| 주소 | `https://gms.ssafy.io/gmsapi/api.openai.com/v1/chat/completions`(`LLM_CHAT_URL`, OpenAI Chat Completions 형식) |
| 모델 | `gpt-5.6-terra`(`LLM_MODEL`) |
| 사용처 | 질문 생성 · 답변 채점 · 결과 생성(분석 작업자), 꼬리질문(에이전트) |

- 주소와 모델 이름은 비밀값이 아니므로 `deploy/prod/compose.yml`에 직접 적혀 있습니다.
- **GMS를 쓸 수 없는 환경**에서는 OpenAI Chat Completions 형식과 호환되는 다른 서비스로 `LLM_CHAT_URL` · `LLM_MODEL` · `LLM_API_KEY`를 바꿉니다. 다만 프롬프트는 위 모델에 맞춰 조정되어 있습니다.

## 4. 미디어 서버(LiveKit)

운영 환경에서는 LiveKit 오픈소스(`livekit/livekit-server:v1.13.10`, `livekit/egress:v1.15.0`)를 서버에 직접 설치해 쓰므로 **외부 가입이 필요 없습니다.**

- API 키와 시크릿은 직접 정해 GitLab 변수에 등록합니다.
  - `LIVEKIT_API_KEY`: 영문 · 숫자 · `_` · `-`만 사용합니다. 배포 스크립트가 이 값을 `livekit.yaml`에 채워 넣기 때문입니다.
  - `LIVEKIT_API_SECRET`: 32자 이상의 임의 문자열(예: `openssl rand -hex 32`)
- 같은 키를 LiveKit 서버, Egress, BE(입장 토큰 서명 · 웹훅 서명 검증), AI 에이전트가 함께 씁니다.
- TURN은 LiveKit 내장 기능을 쓰며, 별도 TURN 서버는 없습니다.
- 개발 서버만 [LiveKit Cloud](https://cloud.livekit.io)를 씁니다. 개발 서버가 NAT 뒤에 있어 미디어 포트를 열 수 없기 때문입니다. 로컬에서 면접방을 확인할 때도 LiveKit Cloud 프로젝트를 만들어 주소와 키를 넣으면 됩니다.

## 5. AWS

모든 리소스는 서울 리전(`ap-northeast-2`)에 있습니다.

### 5.1 S3

| 버킷 | 용도 | 폴더(접두사) |
|---|---|---|
| `hanggeut-a301-prod` | 운영 파일 | `profile/`(프로필 사진), `recordings/raw/`(녹화 원본 트랙), `recordings/`(합친 mp4), `backup/`(DB 백업) |
| `hanggeut-a301-company` | 회사 카드 공용 버킷(선택, 8장) | 파이프라인이 올린 카드 파일과 manifest |

S3 버킷 이름은 전 세계에서 하나만 쓸 수 있으므로, 새로 만들 때는 다른 이름을 쓰고 `deploy/prod/compose.yml`의 `S3_BUCKET`(BE · AI)과 `deploy/prod/backup.sh`를 함께 수정합니다.

운영 버킷은 다음과 같이 설정합니다.

| 항목 | 값 |
|---|---|
| 퍼블릭 액세스 | 모두 차단합니다. 파일은 Presigned URL로만 주고받습니다 |
| ACL / 암호화 / 버전 관리 | ACL 비활성화(버킷 소유자 적용) / SSE-S3 / 사용 안 함 |
| CORS | 허용 출처 `https://hangguet.co.kr`, 메서드 `GET` · `PUT` · `HEAD`, 허용 헤더 `content-type`, 노출 헤더 `ETag` |
| 버킷 정책 | `aws:SecureTransport`가 false인 요청은 거부(HTTPS만 허용) |
| 수명 주기 | 완료되지 않은 멀티파트 업로드는 7일 뒤 삭제 |

CORS를 설정하지 않으면 브라우저에서 프로필 사진을 올릴 때(Presigned URL로 `PUT`) 요청이 막힙니다. 도메인을 바꾸면 허용 출처도 함께 바꿉니다.

### 5.2 IAM 사용자

콘솔 접근 권한 없이 액세스 키만 발급합니다. 키를 역할별로 나눠 두어, 키 하나가 유출되더라도 피해가 그 키의 권한 안으로 한정되게 했습니다.

| 사용자 | 변수 | 사용처 | 허용 권한 |
|---|---|---|---|
| `a301-prod-app` | `AWS_ACCESS_KEY_ID` · `AWS_SECRET_ACCESS_KEY` | BE(프로필 사진), AI(녹화 합치기), DB 백업 | `profile/*`: `PutObject` · `GetObject` · `DeleteObject`<br>`recordings/*` · `backup/*`: `PutObject` · `GetObject` · `AbortMultipartUpload` · `ListMultipartUploadParts`<br>버킷: `ListBucket` · `GetBucketLocation` |
| `a301-prod-egress` | `LIVEKIT_EGRESS_S3_ACCESS_KEY` · `LIVEKIT_EGRESS_S3_SECRET` | BE가 녹화 요청에 담아 Egress에 전달 | `recordings/*`: `PutObject` · `GetObject` · `AbortMultipartUpload` · `ListMultipartUploadParts`<br>버킷: `GetBucketLocation` |

- 앱 키에 `ListBucket` 권한이 없으면, 없는 파일을 조회할 때 S3가 404 대신 403을 돌려주어 BE가 오류로 처리합니다.
- 회사 카드 버킷을 쓴다면 앱 키에 `hanggeut-a301-company` 읽기 권한을 추가합니다.

### 5.3 EC2 Auto Scaling · SSM(선택)

AI 에이전트와 녹화(Egress)를 메인 서버에서 분리할 때만 필요합니다. 쓰지 않아도 서버 한 대로 서비스가 동작합니다.

| 리소스 | 내용 |
|---|---|
| ASG `a301-prod-agent` | `t3.small`, Amazon Linux 2023, 1~5대. 평균 CPU 40% 기준으로 대수를 조정합니다 |
| ASG `a301-prod-egress-node` | `t3.medium`, 1~2대 |
| 수명 주기 훅 | 인스턴스 종료 시 최대 3900초 대기(진행 중인 면접 · 녹화를 마친 뒤 종료) |
| SSM Parameter Store | `/a301/prod/agent/*` · `/a301/prod/egress/*`(SecureString). LiveKit · Redis 주소와 키, 외부 API 키, 이미지 태그를 둡니다 |
| IAM | 인스턴스 역할 2개(`deploy/asg/iam/*-instance-policy.json`)와 CI용 사용자 `a301-prod-agent-ci`(`ci-agent-refresh-policy.json`). CI용 사용자의 키는 `AGENT_REFRESH_AWS_ACCESS_KEY_ID` · `AGENT_REFRESH_AWS_SECRET_ACCESS_KEY`로 등록합니다 |

생성 순서와 매개변수 전체 목록은 [`deploy/asg/README.md`](../deploy/asg/README.md)에 있습니다.

## 6. 도메인 · 인증서

### 6.1 도메인 · Cloudflare DNS

- 도메인 `hangguet.co.kr`은 가비아에서 구매했고, 네임서버를 [Cloudflare](https://dash.cloudflare.com)로 위임했습니다.
- Cloudflare는 **DNS 용도로만** 씁니다. A 레코드 4개(`hangguet.co.kr` · `rtc.` · `turn.` · `grafana.`)가 서버 공인 IP를 가리키도록 만들고, **프록시는 꺼 둡니다(회색 구름).** TURN/TLS와 WebRTC 미디어는 HTTP 프록시를 통과하지 못하기 때문입니다.
- 인증서 발급용 API 토큰은 이 도메인 영역의 **DNS 편집 권한만** 주어 만들고, 서버의 certbot 설정 파일(권한 600)에 둡니다. GitLab 변수에는 등록하지 않습니다.

다른 DNS 서비스를 써도 됩니다. 이 경우 certbot 발급 방식만 해당 서비스에 맞게 바꿉니다.

### 6.2 Let's Encrypt

- certbot과 Cloudflare DNS 플러그인(DNS-01 방식)으로 발급하므로 80번 포트로 검증할 필요가 없습니다.
- 인증서는 웹용(`hangguet.co.kr` · `rtc.` · `grafana.`)과 TURN용(`turn.hangguet.co.kr`) 2개입니다.
- `certbot.timer`가 하루 두 번 갱신 여부를 확인하고, 갱신되면 스크립트가 Nginx를 reload하거나 LiveKit을 재시작합니다.
- 발급 명령과 갱신 스크립트는 [01_빌드_배포_매뉴얼.md](01_빌드_배포_매뉴얼.md)의 5.2 ④와 6.4에 있습니다.

## 7. 빌드 · 배포 · 운영 도구

### 7.1 GitLab(SSAFY)

- 저장소 주소는 `https://lab.ssafy.com/s15-final/S15P31A301`입니다.
- 비밀값은 CI/CD Variables에 둡니다(01 문서 3.2). `master`는 보호 브랜치이고, 변수는 Protected로 등록합니다.
- 운영 서버의 shell 러너(태그 `a301-prod`, protected)가 배포를, Docker가 설치된 러너(태그 `a301-mock-deploy`)가 이미지 빌드를 맡습니다. 새 환경에서는 같은 태그로 러너를 등록하거나 `.gitlab-ci.yml`의 태그를 바꿉니다.

### 7.2 Docker Hub

[Docker Hub](https://hub.docker.com)에 비공개 저장소를 하나 만듭니다(운영은 `hanggeut/a301`). 무료 플랜에서는 비공개 저장소를 하나만 만들 수 있어, 저장소 하나에 서비스를 태그로 구분해 올립니다(`be-<SHA>` · `fe-<SHA>` · `ai-<SHA>` · `admin-<SHA>`).

액세스 토큰은 Account settings > Personal access tokens에서 용도별로 발급합니다.

| 토큰 | 권한 | 변수 | 사용처 |
|---|---|---|---|
| push용 | Read & Write | `DOCKERHUB_PUSH_TOKEN` | `prod-build` 작업 |
| pull용 | Read-only | `DOCKERHUB_PULL_TOKEN` | `prod-deploy` 작업(운영 서버) |
| ASG pull용(선택) | Read-only | SSM `dockerhub-token` | 에이전트 ASG 인스턴스 |

- 다른 계정이나 저장소를 쓴다면 `.gitlab-ci.yml`의 `.prod` 항목에 있는 `DOCKERHUB_USER` · `DOCKERHUB_REPO`를 바꿉니다.
- 토큰 권한을 「Public Repo Read-only」로 만들면 로그인은 되지만 비공개 저장소의 이미지를 받을 수 없습니다. 반드시 「Read-only」로 만듭니다.

### 7.3 Tailscale(선택)

ASG 인스턴스가 사설망으로 메인 서버의 LiveKit · Redis에 접속할 때 씁니다. ASG를 쓰지 않으면 필요 없습니다.

- [Tailscale](https://login.tailscale.com) 무료 플랜으로 tailnet을 만듭니다.
- 메인 서버는 `tag:a301-main`, 인스턴스는 `tag:a301-agent` · `tag:a301-egress` 태그로 가입시킵니다. 접근 규칙(ACL)은 인스턴스에서 메인 서버의 7880 · 6379 · 9090 · 3100 포트로 가는 연결만 허용합니다.
- 인스턴스는 부팅할 때 **OAuth 클라이언트 비밀값**(SSM `tailscale-auth-key`)으로 가입합니다. 일반 가입 키는 만료 기한이 있어 쓰지 않습니다.
- 메인 서버는 `sudo bash deploy/asg/main-tailscale.sh prod`로 가입시키고, 출력된 IP를 GitLab 변수 `MAIN_TAILSCALE_IP`에 등록합니다.

### 7.4 모니터링 · 알림

| 도구 | 내용 |
|---|---|
| Grafana · Prometheus · Loki | 운영 `compose.yml`에 포함되어 있어 가입이 필요 없습니다. 주소는 `https://grafana.hangguet.co.kr`이고, 관리자 비밀번호는 `GRAFANA_ADMIN_PASSWORD`입니다 |
| Mattermost | Grafana 알림(서비스 중단 · 메모리 · 디스크 등)과 SonarQube 분석 결과를 Incoming Webhook으로 받습니다. 웹훅 주소는 저장소가 아니라 Grafana와 SonarQube 화면에서 설정합니다 |
| SonarQube | 자체 서버에 설치해 MR마다 정적 분석을 합니다. `SONAR_HOST_URL` · `SONAR_TOKEN`을 GitLab 변수로 등록합니다. 서비스 실행과는 관계가 없습니다 |

## 8. 선택 기능: 회사 카드 파이프라인

지원서의 회사명에 맞는 회사 정보(사업 방향 · 인재상 · 최근 이슈)를 미리 만들어 두는 기능입니다. 로컬 PC에서 Airflow로 따로 실행하며, **이 기능이 없어도 서비스는 동작합니다.** 회사 카드가 없으면 자기소개서와 직무 정보만으로 질문을 만듭니다. BE의 `COMPANY_S3_BUCKET`을 비우면 회사 카드를 적재하지 않습니다.

| 서비스 | 용도 | 가입 · 발급 | 변수(`company-pipeline/.env`) |
|---|---|---|---|
| DART 오픈API | 사업보고서 수집 | [opendart.fss.or.kr](https://opendart.fss.or.kr)에서 인증키 신청 | `DART_API_KEY` |
| 네이버 검색 API | 뉴스 기사 수집 | [developers.naver.com](https://developers.naver.com)에서 애플리케이션 등록(검색 API) | `NAVER_CLIENT_ID` · `NAVER_CLIENT_SECRET` |
| SSAFY GMS | 요약용 LLM · 임베딩 | 3.4와 같은 키 | `LLM_CHAT_URL` · `LLM_MODEL` · `LLM_API_KEY`, `EMBED_URL` · `EMBED_MODEL` · `EMBED_API_KEY` |
| AWS S3 | 완성한 카드 업로드 | IAM 사용자 `a301-company-pipeline`(공용 버킷 쓰기 권한) | `CARD_S3_BUCKET` · `CARD_AWS_ACCESS_KEY_ID` · `CARD_AWS_SECRET_ACCESS_KEY` |

실행 방법은 [`company-pipeline/pipeline/README.md`](../company-pipeline/pipeline/README.md)와 [`company-pipeline/airflow/README.md`](../company-pipeline/airflow/README.md)에 있습니다.
